## conv.js 가 하는 일

1. Tailwind 유틸리티 → 실제 CSS 선언 1:1 번역(미지원 클래스가 있으면 콘솔에 리포트하고 멈추지 않음).
2. 레이어명 보존: `id="skh-<레이어명>"`(중복은 `_2`), `class="skh-<레이어명> n<노드id>"`, `data-name`/`data-node-id`.
   스타일은 노드 id 기반 유일 클래스(`.n64_3367`)에만 건다.
3. 텍스트 상자 고정(위 `figma-node-sizes.json`).
4. Figma 코드 출력이 못 담은 값 2건 보정 — 원본 SVG export 에서 읽어 되살린다.
   - `Header`(64:3855): 프레임 stroke 가 실제로는 **가로 그라디언트**(투명→#788188 60%→#EDECED→투명).
     이미지 위에 그려지는 선이라 오버레이 `div`(`skh-Header/Stroke`)로 얹는다.
     헤더 배경 이미지도 패턴 변환이 비균등 스케일이라 원본 값(-67.5, 1, 2055×58)을 직접 준다.
   - `Event List`(64:3894): 4px 테두리가 흰 단색이 아니라 **가로 그라디언트**.
     패널이 반투명(흰 10%)이라 배경 2겹 기법은 못 쓰고, `::before` + 마스크 링으로 재현한다(라운드 코너 유지).
5. Figma 의 이미지 채우기는 **border box** 기준인데 CSS 절대배치는 padding box 기준이라,
   테두리가 있는 부모 안의 `inset:0` 자식은 음수 위치 + `calc(100% + 2×테두리)` 로 되돌린다.

### 글자 편집('패널편집' > 내용 수정)

스튜디오 사이드바의 **패널편집**을 켜면 이 화면의 **모든 글자(157개 `<p>`)**를 그 자리에서 고칠 수 있다.

- `index.html` 의 `DTSEL` 에 `.skh-root p` 를 넣어 앱의 기존 글자 편집 machinery(자동 저장 `wemb-dt-content`,
  '전체 기본값으로 되돌리기' 연동)에 그대로 태웠고, `applySkhynixHub()` 끝에서 `__dtRecaptureDefaults(false)` 로 다시 수집한다.
- 라이브 피드로 **나중에 생긴 이벤트 행**은 그 목록에 없으므로, live 레이어가 `dt-content-editing` 클래스를 감시해
  누락된 `<p>` 에도 `contenteditable` 을 붙인다. 편집 중에는 **AUTO 피드를 멈춘다**(고치는 중에 행이 갈리면 편집이 날아간다).
- **고친 글자는 라이브 값이 덮지 않는다**: `claimed()` 가 '내가 마지막에 쓴 값과 다르면 사용자 것'으로 판정하고,
  굴러가던 tween 도 다음 프레임에 손을 뗀다. 되돌리기 버튼을 누르면 플래그를 지워 다시 라이브로 흐른다.
- 한 줄 텍스트라 Enter 는 막고, 붙여넣기는 서식 없이 받는다. 편집 중 클릭은 버튼 동작(칩 필터·AUTO·폴드)으로 치지 않는다.

**여기서 밟은 함정:**
- 스튜디오는 화면 전체가 `transform: scale` 로 축소돼 있다 → 높이를 잴 때 `getBoundingClientRect()`(화면 픽셀)를 쓰면
  배율만큼 작게 잡힌다. **`offsetHeight`(레이아웃 픽셀)로 재야** 막대·행 높이가 맞는다.
- 이벤트 행 '틀'을 원본 행 참조로 들고 있으면, 그 행이 목록에서 빠진 뒤 `offsetHeight` 가 0 이 돼 새 행이 납작해진다 → 복제본으로 보관.
- 접기/펴기 이동값을 CSS 변수로만 바꾸면 크롬이 옛 계산값을 붙들고 전환을 다시 돌리지 않는 경우가 있다 → 인라인 `transform` 으로 직접 쓴다.
- 상시 애니메이션(예: 화재 심볼 호흡)은 '가만히 있을 때의 그림'을 Figma 와 다르게 만든다 → 뺐다(원하면 주석 해제).

## 화면 비율 · 반응형 (`relayout()` in skhynix-hub-live.js)

시안은 **1920×1080 기준**으로 그리되, 보이는 영역을 **UI 전체가 꽉 채운다**. 잘라내기(cover)도, 비율 왜곡(늘이기)도 쓰지 않는다.

방식: **균일 배율 + 캔버스 확장 + 블록 재정렬**

1. `S = min(W/1920, H/1080)` — 글자·위젯은 이 배율로만 커진다(왜곡 0).
2. 캔버스를 `VW = W/S`, `VH = H/S` 로 넓힌다 → 영역을 남김없이 덮는다(둘 중 하나는 정확히 1920 또는 1080).
3. 늘어난 만큼(`exW`,`exH`)을 블록에 나눠 준다 — 전부 Figma 원본 좌표에서 유도한 값이라 **정확히 16:9 면 원본과 같은 그림**이 된다.
   - `Header` 폭 = VW, `justify-content:space-between`(브랜드/시계/액션이 양 끝·가운데로), 배경 메시 이미지도 같은 비율로 늘림
   - `Dashboard Grid` 폭 = 1846 + exW → 좌우 위젯 열이 양 끝에 붙는다
   - 좌/우 `Column` 높이 = 916.5 / 906.5 + exH, `space-between` → 위젯 크기는 그대로, 사이 간격만 벌어진다
   - `Event List` 폭 = 1846 + exW, top = VH − 328(펼침) / VH − 54(접힘) → 접기 이동량 274px 은 그대로
   - `Background`·`Nav Cluster` 는 캔버스 한가운데 유지(3D 칩과 둘레 심볼), 바탕 이미지만 캔버스 전체를 덮음
4. `ResizeObserver` 로 영역이 바뀔 때마다 다시 계산한다.

`display:contents` 였던 묶음(Background·Nav Cluster)은 실제 상자로 바꿔야 통째로 옮길 수 있다(자식 좌표계는 1920×1080 그대로라 그림은 안 변한다).
그 상자가 화면을 덮으므로 `pointer-events:none` 을 주고 내비 심볼만 다시 받는다.
스튜디오에서는 이 시안에 한해 `canvas1920`(1920 고정 캔버스 + 통짜 축소) 모드를 **끈다**.
