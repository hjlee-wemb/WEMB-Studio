## 이 파일에서 새로 배운 함정

① **컴포넌트를 부를 때 크기가 사라진다.** Figma 출력은 뿌리에
`className={className || "relative size-[10px]"}` 를 쓰는데, 호출부가 className 을 넘기면 기본값이
통째로 버려진다. 이벤트 등급 배지의 전구(`Bulb`)가 그랬다 — 호출부가 자리만 주고 크기를 안 줘서
상자가 0x0 이 되고 **색점이 통째로 사라졌다**(Figma 렌더 대조로 발견). → `patch-compsize.js` 가
'호출부에 크기 클래스가 하나도 없으면 기본값의 크기만 이어 붙인다'.

② **`background-image` 의 에셋 경로에 `{{B}}` 가 안 붙는다.** conv.js 는 `src=` 와 `mask*` 만
처리하고 있었다. 이 시안은 판 텍스처를 `style={{backgroundImage:url(…)}}` 로 받아서, 미리보기에서는
우연히 맞고 **스튜디오에서는 404** 가 났다(판 텍스처가 사라진다). → `patch-bgurl.js`.

③ **`mix-blend-mode` 는 `<img>` 로 부르면 죽는다.** Ack 단추·접기 단추·자산 타일 바탕은 광택을
`mix-blend-mode:overlay` 로 얹는데, 브라우저는 그 그림을 독립 이미지로 그려서 blend 의 바탕이
사라진다 → 광택이 **흰 삼각형**으로 찍힌다(Ack 단추가 하얗게 떴다).
- 고치는 법: 그 그림만 **인라인 `<svg>`** 로 심는다(`INLINE_SVG`). 그러면 페이지 바탕과 섞여
  Figma 와 같아진다.
- 단, **전부 인라인하면 안 된다.** `group-bg`·`group-count-*` 는 `<img>` 쪽이 원본과 같고,
  인라인하면 blend 가 페이지까지 먹어 자산 타일 네 개의 테두리가 은색으로 떠올랐다.
  Figma 의 blend 격리 범위는 노드마다 다르다 — **한 장씩 렌더 대조로 정한다.**
- `isolation:isolate` 는 도움이 안 된다(오히려 바탕이 투명해져 더 하얘진다).

④ **design context 가 '마스터 기본 그림'을 내보낼 때가 있다.** 자산정보현황 제목 아이콘은
캔버스에 목록 글리프(`svg-section02`)가 놓여 있는데 dc 는 마스터 기본인 위치 핀(`svg-section01`)을 줬다.
제목 밑줄(`line.svg`)도 viewBox 가 달랐다(549.656 vs 517 → 쐐기가 일찍 끝난다).
→ 그 노드를 캔버스에서 `exportAsync({format:'SVG'})` 로 직접 뽑아 쓴다(`patch-canvas-asset.js`).

⑤ **인스턴스에 걸린 회전이 컴포넌트 출력에 안 실린다.** 층 선택 패널의 접기 단추는 Figma 에서
`rotation:-90` 인데 dc 에는 그 회전이 없다(자산정보현황 쪽은 `rotate-90` 래퍼가 실려 있다).
→ 라이브 레이어가 `.pk-rot90` 으로 세운다. Figma 회전 부호는 CSS 와 **반대**다(-90 → `rotate(90deg)`).

⑥ **반응형 엔진의 '전면 배경' 판정을 고쳐야 했다.** HANA 엔진은 `높이 ≥ 85% || 폭 ≥ 99%` 를 전면
배경으로 보고 세로로 늘린다. 이 시안은 **폭 1920 짜리 줄이 셋**(헤더·브레드크럼·이벤트 현황)이라
헤더가 56 → 240 으로 늘어났다. → `&&` 로 바꾸고(`mk-live.js` 의 `tweak`), 블록이 어디에 붙는지는
추정 대신 **표(`ANCHOR`)로 못 박았다** — 헤더 바로 밑에 브레드크럼이 붙어 있어 비례 배분을 하면
그 사이가 벌어지기 때문. 화면이 6장이 되면서 그 표는 **node id 가 아니라 레이어명**으로 잡는다
(`Background` `Header` `Breadcrumb` `Building Image`/`Floor Plan` `Sidebar` `Popup/…` …) —
여섯 장이 같은 골격을 쓰지만 node id 는 화면마다 다르기 때문(이름은 Figma 에서 통일해 두었다).

### 화면 5장을 더 받으며 배운 것

⑦ **화면마다 같은 그림이 새 파일로 쌓인다.** design context 는 화면별로 새로 내보내므로 SVG 안의
그라디언트·필터 id 번호가 매번 다르다(`paint0_linear_0_1328` ↔ `_0_1344`). dl.js 는 내용 해시로
중복을 지우니 이 번호 차이만으로 `btn-ack-bg-2.svg`, `-3.svg` … 가 줄줄이 생긴다(222장까지 늘었다).
→ `dedupe-assets.js` 가 'id 번호만 지운 정규형'이 같으면 한 파일로 모은다(117장으로 줄었다).
**그리고 dl.js 를 다시 돌리면 캔버스에서 직접 뽑아 둔 그림(함정 ④의 `line.svg`)도 원격 기본값으로
갈아 끼워진다** — `pin-assets.js` 로 다시 못 박을 것.

⑧ **MCP 응답이 너무 크면 대화로 오지 않는다.** 화면 하나의 design context 가 13~20만 자라
`tool-results/*.txt` 로 떨어진다. 그 원문을 손으로 옮겨 적으면 한 글자만 어긋나도 파서가 엉뚱한 DOM 을
만든다 → `save-dc.js` 로 **파일 → 파일**로 옮긴다. TEXT 상자 덤프(`use_figma`)는 반대로 20kb 에서
잘리니, `check-meta.js` 로 '기존 meta 로 안 덮이는 id'만 골라 조금씩 받는다.

⑨ **라이트 시트의 '흰 막'은 자리를 무너뜨릴 수 있다.** 판 텍스처(body.png) 위에 덮는 막은
`position:relative` + `::before` 로 만드는데, 이미 `absolute` 로 자리를 잡은 판에 그 규칙을 덧씌우면
판이 통째로 왼쪽 끝으로 튀어나간다(전체층 자산정보현황이 그랬다). → conv.js 가 '그 노드가 이미
자리를 잡았는지'를 함께 넘기고, light.js 는 static 인 것에만 position 을 준다.
어느 노드가 텍스처를 쓰는지도 **손으로 적지 않는다** — conv.js 가 훑어서 모은다(예전엔 메인 화면의
노드 클래스 두 개가 박혀 있어서, 새 화면의 판이 까맣게 남았다).

⑩ **원본이 '반투명 유리'인 판은 라이트에서 글자가 겹친다.** 팝업 판은 면 opacity 가 0.5라 어두운
바탕에서는 짙게 읽히지만, 밝은 바탕에서는 뒤의 목록이 그대로 비친다(면만 불투명하게 세우면 이번엔
짙은 판에 짙은 글자가 된다). → `Popup/… > Background::after` 로 **흰 막**을 덮는다. 글자는 Body 가
Background 뒤에 오므로 막 위에 남는다. 도면(Floor Plan)은 '어두운 바닥 + 흰 선' 그림이라 라이트에서
색을 뒤집어 '밝은 바닥 + 짙은 선'으로 만든다.

⑭ **판은 넓어지는데 그 안쪽 조각은 1920 에 박혀 있다.** 캔버스를 넓히면(작업 영역이 16:9 보다 넓을 때)
헤더·브레드크럼·이벤트 현황 같은 '가로를 꽉 쓰는 판'은 반응형 엔진이 넓혀 주지만, 그 **안쪽** 조각 중
Figma 가 `width:1920px` 로 박아 준 것은 그대로 남는다. 헤더가 그랬다 — `Header > Background`
(+`Fill`·`Accent Line`)와 `Header > Content` 가 2560 폭에서 가운데 1920 만 칠해, 좌우 320px 씩
맨바닥이 드러났다(6화면 공통. 사용자가 `#pkm-Background_5` 로 잡아 줬다).
→ `installWideFit` 이 **한 번 '고정'을 푼다**: absolute 조각은 `left:0/right:0/width:auto`,
흐름 안의 조각은 `width:100%`. 기준 크기(1920)에서는 결과가 한 픽셀도 달라지지 않는다(0.00~0.11% 확인).
**가운데 맞추려고 걸어 둔 `translate(-50%)` 는 반드시 함께 걷을 것** — 안 걷으면 폭만 넓어진 채
왼쪽으로 절반만큼 밀린다(그 상태를 한 번 만들었다).

⑮ **백틱 문자열 안의 정규식은 소리 없이 망가진다(⑫의 재발).** `installWideFit` 의 matrix 판독에서
또 당했다 — `/^matrix\(([^)]+)\)$/` 가 `/^matrix(([^)]+))$/` 로 나가 `mid` 판정이 늘 false 였다.
이제 `mk-live.js` 가 **내보내기 전에 생성물을 훑어** 이 모양(괄호·대괄호 이스케이프가 벗겨진 정규식)을
찾으면 경고하고 종료 코드 1 로 끝낸다. 백틱 구역에서는 정규식 대신 `indexOf/slice` 를 쓸 것.

⑯ **팝업 자리는 표(`ANCHOR`)로 못 박지 말 것.** ⑭ 를 고치고 나서 '넓히면 팝업이 오른쪽으로 밀리지
않을까' 싶어 `Popup/` 을 한 줄로 dx 0.5(가운데)로 박았더니, 원본이 **왼쪽 목록에 붙여 둔 팝업**까지
가운데로 끌려갔다 — 종합현황 팝업이 2560 에서 좌 156 → 476 으로 목록에서 떨어져 나갔다.
이 시안의 팝업은 두 갈래다: **가운데 띄운 것**(Ack 알림 · 자산 상세)과 **왼쪽에 붙인 것**
(종합현황 · 이벤트 리스트). `measureAnchors` 가 잰 값이 이미 각각 0.5 와 0 을 맞히므로
**재는 쪽을 믿고 표에서 빼는 것이 맞다**(그 줄을 지웠다). 표는 '재도 못 맞히는 것'에만 쓴다.

## 인터랙션·라이브 (`src/posco-live.js`)

- **반응형** — 1920x1080 기준을 유지한 채 캔버스를 넓혀 여백 없이 채운다(통짜 축소 아님).
  판이 넓어질 때 그 **안쪽**의 1920 고정 조각(헤더 바탕·헤더 내용 …)도 함께 펴진다(`installWideFit`, 함정 ⑭).
- **실시간 시계** — 헤더 `2026/09/14` + `14:19:33` 매초 갱신(원본 서식 그대로).
- **마우스 오버/눌림** — 메뉴·내비·버튼·등급 칩·건물 라벨·표의 줄(34곳).
- **층 고르기** — 누르면 그 층만 켜진다. 색은 새로 짓지 않고 Figma `btn-floor` 의
  `Status=hover`(16:9160) · `Status=active`(16:9161) 값을 그대로 쓴다.
- **접기·펴기** — 이벤트 현황(Fold 단추, 재서 205px) · 층 선택 패널(617 → 54) · 자산정보현황.
- **알림 티커**(`#pkm-Alert Ticker`) — 원본 설계가 티커다(상자 `overflow:clip` + 글자 `nowrap`)라서
  **글자는 늘 흐른다**: 42px/초로 왼쪽으로 빠지고 64px 여백 뒤 오른쪽에서 다시 들어온다(한 바퀴 ≈ 19초).
  내용은 지어내지 않고 원본 한 줄을 돌린다. 자리는 `transform` 이 아니라 CSS **`translate` 속성**으로 옮긴다 —
  원본이 걸어 둔 `transform: translateY(-50%)` 를 덮어쓰면 글자가 위로 튄다.
  글자 폭은 conv.js 가 Figma 값(367px)으로 못 박아 두어 겉보기엔 상자와 같으므로, 실제 길이는 안쪽 `<p>` 의
  `scrollWidth` 로 잰다(예전엔 '넘칠 때만 흐른다'는 조건이라 아예 안 움직였다).
  판 전체(`.pk-tickerbar`)는 밝기만 2.4초 주기로 오간다.
- **경고 심볼**(`#pkm-1:454`, 티커 왼쪽) — 경보등처럼 **커졌다 작아지고**(scale 1 → 1.13) 링이 퍼져 나간다
  (`::after`, 2.4초 주기로 티커 바와 같은 박자). 크기는 `transform` 이 아니라 CSS **`scale` 속성**이라
  원본 transform 을 건드리지 않는다. 링 색은 시안의 위험색 `rgb(244,48,80)`(전구 critical 그라디언트 시작색)
  그대로이고, 라이트에서는 `rgba(197,26,52,.5)` 로 내린다. 그림·색·자리는 원본 그대로다.
- **라이브 데이터** — 등급 카운트(CR·MA·MI·WA·NO)와 자산 수치가 원본 값 언저리에서 흔들리고,
  이벤트 표는 7초마다 맨 아래 줄이 맨 위로 올라오며 발생시각이 '지금'으로 다시 찍힌다.
- **발생시각 되찍기** — 열 때마다 표의 시각을 최근으로 옮긴다(공용 `src/recent-time.js`).
- 전부 CSS transition/rAF 라 패널편집·테마 전환과 충돌하지 않는다(`editing()` 중에는 멈춘다).

규칙 셋.
① **나브는 글자로 잡는다.** 같은 나브인데 레이어 이름이 화면마다 다르다
(`Nav Item/Overview (Selected)` · `item01_on` · `item02_off` · `item01_off`) — 이름으로 잡으면 새 화면에서 어긋난다.
'기본위치'는 시점 되돌리기라 이동이 아니어서 고르기만 남긴다.
② **지금 화면과 같은 곳으로는 잇지 않는다.** 그래야 종합현황 화면의 나브가 '팝업 열기'로,
Ack 화면의 Ack 단추가 '알림창 열기'로 남는다(제자리 동작이 이동보다 먼저다).
③ **없는 자리는 떠다 심는다.** 출입동선 화면만 나브가 '부지이동 · 전체보기'뿐이라 다른 화면으로
넘어갈 자리가 없었다. 단층(1:2400)의 나브 타일 **둘을 원본 그대로 잘라다**(conv.js `GRAFT`) 같은 줄
앞에 끼웠다 — 손으로 그리지 않으므로 그림 · 글자 · 크기가 원본과 같다(둘 다 40x58, 줄은 flex gap 9).
순서는 다른 화면과 같게 **종합현황 · 출입동선 · 부지이동 · 전체보기**.
그 대가로 출입동선의 픽셀차가 5.43 → 5.51% 가 됐다(늘어난 타일 둘, 아래 검증 ①).
심다가 두 가지를 고쳤다 —
`findNode` 는 **식으로 된 id 를 못 읽었다**(`id={isChartOn ? "node-1_1000" : …}`). 나브 타일은 컴포넌트라
id 가 전부 식이어서 영영 못 찾았다 → 출력할 때와 같은 방법으로 그 자리의 scope 로 풀어서 견준다.
그리고 `GRAFT` 에 **자리(at)와 '보이게 심기'(show)** 를 더했다(예전엔 늘 끝에, 늘 `hidden` 이었다 —
HANA 의 드롭다운은 JS 가 펴는 것이었기 때문).

④ **가는 길은 셋.** 스튜디오 안에서는 `window.__gotoPoscoScene`(`js/templates/posco.js`)이
**같은 프로젝트에 그 장면으로 만든 형제 화면이 있으면 그 화면을 연다**(`?screen=<id>`, 홈과 같은 '여는 막'을 씌운다).
작업공간은 화면 하나만 여는 구조라, **캔버스만 바꿔치우면 열린 화면 기록(tplScene)과 어긋나**
새로고침에 되돌아가고 고친 글자가 엉뚱한 화면에 저장된다. 형제가 없으면 제자리에서 장면만 바꾸고,
낱장 미리보기(`src/posco/*.html`)로 열었을 때는 파일 이동(`./overview.html`, 쿼리 유지)이 맡는다.

이걸 붙이다가 **묵은 것 하나가 드러났다** — 종합현황 팝업의 '여는 자리'가 `Nav Bar > *`(나브 전체)라
옆의 **출입동선을 눌러도 종합현황이 떴다**. 팝업은 제 이름이 붙은 자리(`Nav Item/Overview`)에만 맨다.

**시안에 목록 판이 없으면 브라우저가 가진 것을 쓴다.** 달력도 건물 목록도 Figma 에 펼친 모습이 없다.
없는 형상을 그려 넣는 대신 **원본 칸 위에 투명한 진짜 입력**(`input[type=date]` · `<select>`)을 덮는다 —
보이는 것은 끝까지 시안이고, 열리는 것은 브라우저(OS) 것이며, 키보드로도 열린다.
목록에 넣을 **내용은 반드시 시안 어딘가에 있는 것**이라야 한다(건물 이름은 전체층 화면 사이드바에서 왔다).

**덮어 둔 입력을 감출 때 지켜야 할 것 셋**(전부 한 번씩 틀려 본 것이다).
① **`color:transparent` 는 펼친 목록까지 지운다.** `<select>` 의 option 이 그 색을 물려받아 목록 글자가
통째로 사라졌다(사용자가 바로 알아챘다) → option 의 색·배경을 **따로 못 박고**, 목록 판은 화면 테마를 따르게
`color-scheme` 을 준다(다크가 기본, 라이트만 속성으로).
② **`opacity:0` 으로 감추지 않는다.** 흐려 둔 입력에는 브라우저가 달력을 띄워 주지 않는다.
글자·배경·겉모습만 지우고, 달력 단추는 **칸 전체로 늘려 투명하게** 깐다 — 그러면 어디를 눌러도 브라우저가
스스로 연다(`showPicker()` 는 '사람이 직접 누른 것'을 요구해 자리에 따라 거부된다. 받쳐 두되 기대지 않는다).
③ **날짜 칸에는 `appearance:none` 을 주지 않는다.** 겉모습을 지우면 달력 단추의 기본 동작까지 사라진다.
그리고 날짜 글자 영역은 `::-webkit-datetime-edit{opacity:0}` 로 — 투명 글자만으로는 초점이 간 조각의
**파란 선택 블록**이 시안 위로 비친다.

**덮어 둔 입력을 드러내지 말 것.** 날짜 선택기의 초점 표시를 `opacity:1` 로 주었더니 브라우저 기본
날짜칸이 시안 위에 그대로 떴다. 초점은 **칸 바깥 테두리**(`:focus-within`)로 보이고, 덮은 입력은 끝까지
투명하게 둔다. 그리고 덮은 입력에 `preventDefault` 를 걸면 `showPicker` 가 없는 브라우저에서 제 동작까지 막힌다.

**'지금 이 화면'은 원본에 없다.** 나브 타일의 켜진 모습은 **그림째 따로**라(chart-1.svg ↔ gate.svg)
겉모습을 맞바꿀 수 없고, 원본은 어느 화면에서나 종합현황이 흰 글자다 — 출입동선 화면에 종합현황 타일을
심으니 '지금 종합현황을 보고 있다'로 읽혔다. 색을 새로 짓지 않고 **누를 때 쓰는 그 파란 빛(`pk-picked`)을
지금 화면의 타일에 미리 얹는다**(출입동선 화면=출입동선 타일, 종합현황 화면=종합현황 타일).
같은 방법으로 자산리스트의 분류 탭도 처음부터 펴져 있는 분류에 맞춰 둔다.
그래서 **가만히 둔 화면이 Figma 와 한 곳 달라진다**(빛 하나). 픽셀 대조는 `?live=0` 이라 숫자는 그대로다.

**'여기 눌린다'는 표시** — 클릭을 붙이는 장치는 전부 `clickable(el, 제목)` 를 지나간다(`unclickable` 로 되돌린다).
한 자리에서 ① 손가락 커서(`pk-click`) ② 키보드 초점(tabindex) ③ 역할(role) ④ 툴팁을 준다.
커서는 상속되므로 안쪽 글자·아이콘 위에서도 손가락이다(원본이 글자를 `<p>` 로 두어 그냥 두면 I-빔이 뜬다).
**패널편집 중에는 이 표시를 걷는다** — 그때는 글자 커서가 맞다(`.dt-content-editing` 규칙).
호버 틴트(`pk-hot`)도 층 버튼의 파란 그라디언트도 없던 자리(팝업 X · 알림의 확인)에만 `pk-lit` 를 더해
**밝아지는 반응**을 준다 — 커서만 바뀌면 눌리는지 확신이 안 선다. 이미 반응이 있는 자리에는 안 붙는다
(중복 강조 방지 — `clickable()` 이 `closest('.pk-hot')` 로 가린다).

함정 — 이 묶음은 생성기의 **템플릿 문자열 안**이라 역따옴표를 못 쓰고, 정규식의 역슬래시가 한 겹
벗겨진다(`\[` → `[`). 팝업 제목의 대괄호 치환이 그래서 조용히 안 먹었다 → indexOf/slice 로 바꿨다.
`use_figma` 로 화면을 고칠 때처럼, **생성물을 열어 정규식이 성한지 확인할 것**.
