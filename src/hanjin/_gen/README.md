원칙
- **글자는 전부 편집 가능한 실제 텍스트**(`<p>`, Pretendard CDN). SVG 로 구워진 글자는 없다.
- **아이콘·그래픽만** Figma 가 내보낸 개별 파일(`src/hanjin/*.svg|png`)을 그대로 쓴다. 손으로 그린 벡터는 하나도 없다.

  스타일 훅은 노드 id 기반 유일 클래스(`n65_2243`)로 건다.

## 파이프라인

```
1) Figma MCP 로 원본을 받아 놓는다 (이미 받아 둔 결과가 이 폴더에 있다)
   get_design_context → dc-<node>.txt        (React+Tailwind 참조 코드 + 에셋 URL)
   get_metadata       → meta-<node>.xml      (노드 이름·좌표·크기 — 검증 기준)
   get_screenshot     → figma-<node>.png     (1920x1080 원본 렌더 — 픽셀 대조 기준)

2) node dl.js                 dc-*.txt 의 에셋 URL 을 전부 내려받아 src/hanjin/ 에 저장
                              (내용 해시로 중복 제거 → asset-map.json)
3) node mk-nodes.js           meta-*.xml → nodes-*.json (브라우저 검증용 노드 상자표)
4) node mk-gauge-assets.js    meter.svg → meter-track.svg + meter-fill.svg (게이지 애니메이션용)
5) node mk-light-assets.js    어두운 바탕 전제 벡터 → *-lt.svg (라이트 테마 사본)
6) node conv.js               ★ 본체 — dc-*.txt → src/hanjin-{control,gate,unload}.js + 미리보기 html
```

`conv.js` 를 고쳐 다시 돌리는 게 정석이다. **생성물(`src/hanjin-*.js`)을 손으로 고치지 말 것.**

## conv.js 가 하는 일

1. **JSX 파서** — Figma 의 React 출력은 컴포넌트 함수·프래그먼트·`{cond && (…)}`·삼항·템플릿 리터럴을 쓴다.
   컴포넌트는 화면마다 한 번씩만 쓰이므로 호출부의 props 로 그 자리에서 펼친다(조건은 실제로 평가한다).
2. **Tailwind → CSS 1:1 번역** — 근사 없음. 번역 못 한 클래스는 콘솔에 리포트한다(현재 0건).
3. **텍스트 상자 고정** — 브라우저 폰트 메트릭이 Figma 와 1~2px 달라 오토레이아웃을 밀어낸다.
   `get_metadata` 가 잰 폭/높이를 텍스트 노드에 그대로 박아 레이아웃을 고정한다(글자는 그대로 편집 가능).
4. **라이트 테마 파생** — `light.js` 의 역할별 대응표를 같은 순회에서 돌려
   `.<접두어>-root[data-theme="light"]` 오버라이드 시트를 함께 뽑는다.
5. **프로토타입 변형 세트 펼치기**(`VARIANT_SETS`) — 화면에는 한 상태만 박제돼 있다(층 선택=2F,
   카메라 프리셋=Step 01). 컴포넌트 세트를 따로 `get_design_context` 로 받아(`dc-65-3345.txt`,
   `dc-116-2166.txt`) **모든 상태를 같은 자리에 다 심고** 대기 상태는 `hidden` 으로 접어 둔다
   (`data-hj-vset` / `data-hj-variant`). 상태마다 속 구조가 30~87 노드씩 달라서
   겉모습 맞바꾸기로는 재현이 안 되기 때문이다. 자리·크기를 정하는 className 은 화면 쪽 것을 물려준다.
6. **통짜 SVG 를 DOM 으로**(`INLINE_SVG`) — `<img>` 로 두면 색을 못 만지는 그림을 인라인 `<svg>` 로 심고
   `stroke`/`fill` 만 클래스로 빼서 라이트 테마·'색 정하기'가 닿게 한다. 형상(`path d`)은 한 글자도 안 건드린다.
   지금은 `border.svg`(하차현황 도크 상세현황 판 테두리) 하나 — `#hju-Asset_37`.
7. **헤더 탭 상태 바로잡기**(`MENU_STATE`) — 원본 시안이 하위 화면에서 두 탭의 상태를 거꾸로 그려 두었다
   (지금 보고 있는 화면이 `통합관제` 아래인데 `대시보드` 쪽에 '선택됨' 그림이 들어가 있었다).
   사용자 확인을 받아 맞바꾼다. 그림은 **원본 파일 그대로** 쓴다 — 같은 모양의 기본/선택 두 벌이 이미 있다
   (140x38 대시보드꼴: 기본 `visual-2` · 선택 `visual-1-*` / 141x39 통합관제꼴: 기본 `visual-2-2` · 선택 `visual-3`).
8. **조각 이식**(`GRAFT`) — 하위 화면에는 원본에 헤더 드롭다운이 없다. 통합관제 화면(65:429)의 드롭다운(65:434)
   서브트리를 **그대로** 잘라 붙인다(`data-hj-graft="dropdown"`, 처음엔 `hidden`). 두 화면의 Header 가 똑같이
   `absolute contents left-40 top-10` 이라 좌표계가 같고, 가로 자리는 `alignDropdown` 이 탭 중심에 맞춘다.

### 이 파일에서 배운 함정

- **테두리(stroke) 정렬** — 이 Figma 출력은 stroke 정렬을 이미 padding 에 반영해서 낸다.
  예: `Tab/Load(65:710)` 폭 208 = `border 1 + px-[33] + Label 140 + px-[33] + border 1`.
  그래서 **CSS border 를 그대로 두는 게 정답**이고, ::after 링으로 빼면 오히려 2px 씩 줄어든다.
  (SK하이닉스 시안은 정반대였다 — 파일마다 다르니 반드시 노드 상자 대조로 판정할 것.)
  예외로 링/바깥 정렬이 필요한 노드만 `RING_STROKE` / `OUTSIDE_STROKE` 에 적어 두었다.
- **인스턴스 안쪽 노드 id** 는 `I65:2504;65:3517` 꼴이다. `:`·`;` 를 클래스명에 그대로 쓰면
  CSS 선택자가 깨지고 **그 규칙 다음 규칙까지 통째로 무시**된다(도크 슬롯이 납작해졌던 원인).
- **퍼센트 inset** 으로 놓인 블록이 섞여 있다. 캔버스를 넓히면 같이 늘어나므로 반응형에서 따로 다뤄야 한다
  (→ `hanjin-live.js` 가 조각별로 '스스로 따라오는 양'을 재서 보정한다).
- **마스크 덩어리** — `Ramp`(65:2368)는 겹겹의 luminance 마스크 110여 노드라 CSS 로 재현이 안 된다.
  `download_assets(format=svg)` 로 그 노드만 통째로 내보낸 `ramp.svg` 한 장으로 갈아 끼웠다.
- **`undefined` 로 넘어온 prop 은 '안 넘긴 것'이다.** Figma 출력은
  `<Component floor={is5F ? "5F" : … : is2F ? "2F" : undefined} />` 처럼 마지막 갈래를 `undefined` 로 낸다.
  이걸 그대로 덮어쓰면 함수 기본값(`floor = "1F"`)이 죽어 **1F 건물 그림이 통째로 사라진다**
  (76노드 → 33노드, 화면에는 납작한 남색 덩어리만 남았다). 자바스크립트 기본값 규칙 그대로,
  값이 `undefined` 면 대입하지 않는다.
- **문자 참조를 색으로 착각하지 말 것.** Figma 는 한글 레이어명을 `id="&#227;&#132;&#180;"` 로 내보낸다.
  `mk-light-assets.js` 의 hex 스캔이 `#132` 를 색으로 바꿔 `&#c2dccf;` 가 되면서 XML 이 깨져
  라이트 테마에서 그림이 안 떴다 → 앞이 `&` 면 건너뛴다(`(?<!&)`).

## 검증

### ① 노드 상자 대조 (기하)
브라우저에서 `[data-node-id]` 요소의 실제 상자를 `nodes-*.json`(=Figma get_metadata) 과 맞춰 본다.

```js
// 1920x1080 으로 띄운 뒤
const N = await (await fetch('/src/hanjin/_gen/nodes-65-2243.json')).json();
[...document.querySelectorAll('[data-node-id]')].filter(el => {
  const m = N[el.dataset.nodeId]; if (!m) return false;
  if (getComputedStyle(el).display === 'contents') return false;
  const r = el.getBoundingClientRect();
  return Math.abs(r.width - m[1]) > 1.2 || Math.abs(r.height - m[2]) > 1.2;
});
```

**최종 결과: 세 화면 3,577 노드 전부 오차 1.2px 이내(불일치 0).**

`sample.js` 로 임의 사각형의 평균색을 두 이미지에서 비교할 수 있다.

## 라이트 테마 (`light.js` · `mk-light-assets.js`)

원본이 **다크** 시안이라 라이트를 파생한다. 형상·좌표는 한 줄도 건드리지 않고 색만 다시 적는다.

- 역할별 대응표(글자 / 면 / 선 / 그림자)를 따로 둔다 — 같은 `#fff` 라도 '표의 행 배경'과
  '컬러 배지 위의 글자'는 다른 색으로 가야 한다.
- 표에 없는 색은 `autoLight()` 가 처리 — 무채색은 명도를 뒤집고, 유채색은 역할에 맞는 명도로 옮긴다.
- 브랜드·경보·차트 계열색은 그대로 둔다(색이 곧 의미).
- **컬러 배지·어두운 막대 위의 글자는 흰색을 유지한다.** conv.js 가 노드마다 '라이트 이후 면 밝기'를
  재서(그라디언트는 가장 밝은 정지색 기준) 어두우면 글자색 변환을 건너뛴다.
- 어두운 바탕 전제로 그려진 벡터 139장은 색만 옮긴 사본(`*-lt.svg`)을 만들어
  `img { content: url(...) }` 로 갈아 끼운다(레이아웃은 그대로).
  `ramp.svg` 는 마스크 구조가 무너져서 사본을 만들지 않는다(`NO_VARIANT`).
- **`light.js` 의 대응표를 SVG 에 그대로 쓰면 안 된다.** 한 번 해 봤더니 카메라 프리셋 판이 남색으로,
  여섯 번째 버튼이 새까맣게 뒤집혔다. 표는 '역할을 아는 CSS 선언'(글자/면/선/그림자)을 전제로 만든 것이라
  `fill`·`stroke` 밖에 모르는 그림에는 맞지 않는다. 그림은 `mk-light-assets.js` 의 heuristic 으로만 옮긴다.
  그 대가로 한 장짜리로 내보낸 판(`Button/View 6`)은 DOM 판보다 살짝 회색이다 — 원본이 통 이미지라 어쩔 수 없다.

**대비 실측**: 라이트 78건 / 다크(원본) 166건이 4.5:1 미만 — 즉 **라이트가 원본보다 대비가 좋다.**
남은 건 전부 원본 브랜드색이 만든 것(주황·초록 배지 위 흰 글자 등)이라 손대면 원본과 달라진다.

## 인터랙션·라이브 (`src/hanjin-live.js`)

`window.initHanjin(root)` 로 화면 하나를 살린다. 형상은 만들지 않고 다음만 얹는다.

- **반응형** — 1920x1080 기준을 유지한 채 캔버스만 넓혀 여백 없이 채운다(통짜 축소 아님).
  블록이 top/bottom/left/right/퍼센트 중 무엇으로 붙어 있는지는 표로 적지 않고
  **캔버스를 100px 넓혀 보고 조각마다 얼마나 따라오는지 재서** 알아낸다 → 화면 3장에 같은 코드가 통한다.
- **실시간 시계**, **마우스 오버/눌림**, **이벤트 현황 접기·펼치기**(펼치면 서랍처럼 위로 올라온다),
  **탭·메뉴 선택 이동**, **게이지·막대·도넛·수치의 실시간 연동 연출**, **도크 슬롯 툴팁**.
- **헤더 드롭다운**은 언제나 `통합관제` 탭 바로 아래 일직선으로 붙는다. 탭은 헤더 가운데 정렬이라
  캔버스가 넓어지면 오른쪽으로 밀리는데 드롭다운은 원본이 left 고정이라 어긋난다 → 매번 탭 위치를 재서 맞춘다
  (`alignDropdown`, 1920 에서의 미세한 차이는 그대로 보존). 항목에 마우스를 올리면 원본의 '선택됨' 모습
  (파란 테두리 + 반투명 파란 판 + 안쪽 광)이 되고, 누르면 그 상태로 굳는다.
- **넓어진 폭을 판 안쪽까지 전달**한다(`STRETCH`). 캔버스를 넓히면 판(1840)은 따라 넓어지지만 그 안의
  내용은 Figma px 폭 그대로라 오른쪽이 빈다. 단계별 차량현황(Body·Stage Flow·Stages·Track·List)과
  이벤트 현황(머리글·표·행)의 폭을 함께 늘리고, 단계 카드는 `space-between` 으로 고르게 벌린다.
  **칸 크기는 그대로 두고 '사이'만 벌어지므로 글자 크기·비율은 왜곡되지 않는다.**
  작업 영역이 16:9 보다 세로로 길면 늘릴 가로 여유가 없어 원본 그대로다(1920 에서 픽셀 동일).
  - `share` — 나란히 놓인 두 판이 늘어난 폭을 **폭 비율대로 나눠 갖는다**(감싼 자리가 `space-between` 이라
    가운데 틈은 원본 그대로 남는다). 입출문현황의 입문/출문 표와 단계별 차량현황/작업현황이 그렇다.
    안쪽(머리글·행·단계 목록)은 그 판이 받은 몫만큼만 넓힌다.
  - `slide` — 칸이 `margin-left` 로 늘어놓인 자리(요일별 하차물량의 막대). 마지막 칸이 새 오른쪽 끝에
    닿도록 간격을 다시 잰다(`ml × (거리+몫)/거리`). 가로축 눈금은 `spread` 로 벌어져 서로 어긋나지 않는다.
  - `scale` + `track` — 값을 길이로 나타내는 막대(층별 차량현황). 눈금자(가로축)가 길어진 비율만큼
    막대도 같이 길어져 '값 대비 길이'가 유지된다.
  - `fill` — 줄을 꽉 채우는 칸들(층별 도크 운영현황의 이름표+수치). 그 줄이 받은 몫을 칸끼리 폭 비율대로
    다시 나눈다. `space-between` 으로 벌리면 가운데가 휑해 원본과 다른 표처럼 보인다.
  - `boxOf` 가 **그 자리를 통째로 덮는 그림(폭이 똑같은 img/svg)** 도 같이 늘린다 — 판 배경·기준선이
    px 폭 그대로 남는 걸 매번 선택자로 적지 않아도 된다.
  - 차트 안쪽 이름(`Plot`·`Grid`·`Data`)은 **게이지에도 똑같이 있다** → `Bar Chart` 밑으로 좁힐 것.
    안 좁혔더니 하차진척률 게이지 원호가 268 → 392 로 늘어나 찌그러졌다.
  - `measureDockBoard`/`applyDockBoard` — 하차현황 **도크 상세현황**은 한 칸짜리 grid 라 조각이 전부
    `margin-left` 로 놓여 있다 → 폭과 `margin-left` 만 고친다. 왼쪽(A·B존)과 오른쪽(D·C존)이 절반씩
    나눠 갖고, 좁은 조각(존 이름표)은 넓히지 않고 '자기 존 안에서의 자리'만큼만 민다.
    안쪽 그림을 늘릴 때는 **판을 통째로 덮는 것만** 골라야 한다 — 도크 칸 안의 작은 ∞ 아이콘까지 늘리면
    화면을 가로지르는 흰 곡선이 된다(그렇게 한 번 깨졌다).
- 선택 이동은 두 상태의 **속 구조가 같을 때만** 겉모습(클래스·이미지)을 맞바꾼다.
  속 구조가 아예 다른 자리(층 선택·카메라 프리셋)는 맞바꾸기 대신 **변형 세트**로 처리한다 —
  `installVariants` 가 `[data-hj-vset]` 을 모아 `hidden` 만 옮기고, 사람이 고친 글자는 같은 자리끼리 옮겨 준다.
- **감춰 둔 변형도 반응형 계산에 포함시킨다**(`unhideVariants`). 감춘 상태는 재 봐야 0x0 이라 보정을
  못 받고, 나중에 드러나는 순간 퍼센트 inset 그대로 부풀어 자리와 비율이 어긋난다
  (2560 폭에서 층 선택이 270 → 361 로 늘어나고 오른쪽 열 전체가 제자리에 눌러앉았다).
  재는 동안만 잠깐 드러내되 **흐름에 참여하는(절대배치가 아닌) 상태는 도로 감춘다** —
  그런 상태까지 펼치면 형제가 아래로 밀려 다른 조각의 기준 위치가 틀어진다.
- **헤더 메뉴 이동**(`installMenu`) — `대시보드`→통합관제(메인), `통합관제`→드롭다운 펼치기/접기,
  드롭다운 항목→그 화면. 스튜디오 안에서는 `window.__openHanjinScreen`, 낱장으로 열었을 때는 파일 이동.
  아직 시안이 없는 `상차현황`·`차량관제` 는 막는다 — **가만히 있을 때의 그림은 원본 그대로 두고**
  (메인 화면은 원본과 픽셀 동일해야 한다) 마우스를 올렸을 때만 흐려지고 `not-allowed` 커서가 뜬다.
  옮겨 심은 드롭다운은 메인 것이라 선택 표시가 `하차현황` 에 박혀 있다 → 지금 화면 항목으로 옮긴다
  (`hj-cur` / `hj-uncur`, 표시 모습은 원본의 선택 상태 그대로. 라이트 값은 생성기가 내는 값과 맞춰 두었다).
  드롭다운에는 `z-index:60` 을 준다 — 원본 DOM 차례로는 뒤에 오는 위젯이 메뉴를 덮어 버린다.
- **검색창**(`installSearch`) — 원본의 `Field` 는 글자를 그려 둔 자리다. 그 `<p>` 를 그대로
  `contenteditable` 로 만들어 실제로 칠 수 있게 한다(`<input>` 을 얹으면 글꼴·자간이 어긋난다).
  안내 문구는 `:empty::before` 로 그리므로 **빈칸일 때의 그림은 Figma 와 같다**(칸 폭도 원본 90px 그대로,
  치는 동안만 Input 안쪽만큼 넓어진다). 입출문현황은 표에서 안 맞는 줄을 감추고,
  하차현황은 맞는 도크 칸·대기 순번을 밝히고 나머지를 뒤로 물린다. 못 찾으면 칸에 분홍 테두리.
- **GS 차량**(`installRadioChip`) — 원본에 '켜짐' 그림이 없어 같은 파일이 이미 쓰는 라디오 표시를 그대로
  얹었다(`box-on.svg` = `box.svg` + 가운데 점, 메인의 `radio-on.svg` 와 같은 색·같은 비율).
- **도크 칸의 차량·샤시번호는 한 번만 정해 둔다**(`dataset.hjPlate` 등). 예전엔 툴팁이 올릴 때마다 새로
  뽑아 같은 칸인데 번호가 달라졌고, 검색이 찾을 대상도 없었다.
- **'패널편집'(글자 수정) 중에는 라이브 갱신을 전부 멈춘다.** 안 그러면 지나간 값이 편집 내용으로 굳는다.

## 스튜디오 연결 (`index.html`)

- 템플릿 `Dashbord: Hanjin main` → `tpl:'hanjin'`, 슬라이드 3장이 화면 3개(`tplScene`: main·gate·unload)로 만들어진다.
- `applyHanjinDT(which)` 가 `#dtStage` 에 `.<접두어>-root` 를 얹고 `initHanjin` 을 부른다.
- 화면 안 헤더 드롭다운(하차현황/입문현황/…)을 누르면 실제로 다른 화면으로 이동한다(`addHanjinSceneLinks`).
- **화면 테마** 다크/라이트 → `TPLTINT.icheonTint(…, HANJIN_OPT)` 가 `data-theme` 을 바꾼다(`wemb-hanjin-mode`).
- **색 정하기** → 같은 함수가 시트의 색을 팔레트로 옮긴다. 시작값(`#2861FF`)이 그대로인 동안은
  원본 색을 그대로 보여 주고, 사용자가 색을 바꾸는 순간부터 따라온다.
- **패널편집** → `DTSEL` 에 `.hjc-root p, .hjg-root p, .hju-root p` 가 들어 있어 화면의 모든 글자를 그 자리에서 고칠 수 있다.

## 검증용 정적 서버

`file://` 은 `fetch` 가 막혀 노드 상자 대조를 못 한다. 검증할 때만 띄운다.

```
node src/hanjin/_gen/serve.js 5503      # http://localhost:5503/src/hanjin/control.html
```

미리보기 페이지는 `?t=light` 로 열면 라이트 테마로 시작한다(픽셀 대조용, 토글 버튼은 숨겨진다).
