## 4.1 아키텍처 개요

WEMB Studio는 **백엔드가 없는 클라이언트 애플리케이션**이다. 모든 로직(파이프라인·테마 생성·검증·렌더·저작·산출)이 브라우저에서 실행되며, 상태는 브라우저 저장소와 URL로 관리한다. 정적 호스팅(GitHub Pages)만으로 배포·운영된다.

화면은 **두 문서**로 나뉜다. 프로젝트를 고르는 **홈(`index.html`)** 과 한 화면을 만드는 **작업공간(`studio.html`)** 이다. 두 문서 안의 화면 이동은 모두 **주소(해시)** 로 표현되어, 새로고침 · 뒤로가기 · 링크 공유가 같은 화면으로 돌아온다.

```
┌──────────────────────────────── Browser (Client) ────────────────────────────────┐
│                                                                                  │
│  index.html — 홈 (약 9KB)                    studio.html — 작업공간 (약 160KB)     │
│  ├─ css: tokens · focus · toast ·            ├─ head: core/projects.js →         │
│  │       launcher · wireframe-mini · dialog  │        app/session.js (화면 맞추기) │
│  ├─ js/core: router · projects · layouts     ├─ css/  base · shell · guide ·      │
│  ├─ js/launcher: templates · home            │        studio · preview · templates │
│  └─ #/projects  #/recent  #/favorites        ├─ js/   core · app · theme · preview │
│     #/trash  #/projects/:gid                 │        templates · studio · ui ·    │
│     #/templates  #/templates/:slug           │        guide · shell · data         │
│                                              └─ #/prd  #/spec  #/flow             │
│                                                 #/wireframe  #/studio[?t=공유]    │
│                                                                                  │
│   홈 ── studio.html?screen=<id>#/studio · ?new=1[&group=<gid>]#/prd ──▶ 작업공간   │
│   홈 ◀──────────────────────────── index.html#/projects ─────────────── 작업공간   │
│                                                                                  │
│   State: localStorage (화면 목록 · 화면별 상태 묶음)  +  URL (어느 화면 · 어느 단계)  │
└───────────────┬─────────────────────────────────────────────┬────────────────────┘
                │ CDN                                         │ External API
         Pretendard 폰트                                 Open-Meteo(실시간 날씨)
         html2canvas-pro(PNG)                            Geolocation(위치)
```

## 4.2 아키텍처 원칙

| 원칙 | 설명 |
|---|---|
| No-Backend | 서버·DB 없음. 정적 파일만으로 완결 |
| Two-Document | 홈과 작업공간은 별개 문서. 홈은 스튜디오 DOM · 템플릿 화면 스크립트(약 12MB)를 받지 않는다 |
| URL-as-State | 주소가 곧 화면 상태. 화면을 바꾸는 코드는 주소만 바꾸고, 그리는 건 라우트가 한다 |
| No-Build | 번들러 없이 전역(classic) 스크립트. `<script>` 순서가 곧 의존 순서, 모듈 간 공유는 `WEMB.*` 네임스페이스 |
| Token-Driven | CSS 변수 토큰이 단일 진실원(Single Source of Truth) — 값 교체로 전 화면 전환. `<link>` 순서가 곧 캐스케이드 순서 |
| Progressive Disclosure | 고급 옵션(미세조정 등)은 필요 시에만 노출, 파이프라인 단계 잠금 |
| Asset-Library | 시각 자산을 정형화해 재사용 컴포넌트/JSON 토큰으로 축적 |

## 4.3 레이어 구성

### 4.3.1 문서와 주소

| 문서 | 주소 | 화면 | 담당 |
|---|---|---|---|
| index.html | `#/projects` · `#/recent` · `#/favorites` · `#/trash` | 프로젝트(폴더) 목록 | `js/launcher/home.js` |
| index.html | `#/projects/:gid` | 프로젝트 안 화면 목록 | 〃 |
| index.html | `#/templates` · `#/templates/:slug` | 템플릿 갤러리 · 상세 | 〃 |
| studio.html | `#/prd` · `#/spec` · `#/flow` · `#/wireframe` | 가이드 페이지 | `js/shell/chrome.js` · `js/guide/guide.js` |
| studio.html | `#/studio` (`?t=` 공유 시안) | 스튜디오 | 〃 |

- **라우터** `js/core/router.js` — `navigate()` 는 pushState 후 동기로 그린다. 뒤로·앞으로·직접 입력은 popstate/hashchange. 라우트가 문자열을 돌려주면 대체 이동(잠긴 단계 · 없어진 항목).
- **단계 잠금** — 잠긴 단계 주소로 들어오면 열린 마지막 단계로 돌린다. 저장된 화면을 연 경우와 공유 시안의 스튜디오는 예외.
- **문서 경계** — 홈에서 작업공간 주소(`#/studio` 등)를, 작업공간에서 홈 주소(`#/templates` 등)를 받으면 상대 문서로 넘긴다. 예전 공유 링크(`#t=…`)는 `studio.html#/studio?t=…` 로 옮겨 연다.
- **작업 세션** `js/app/session.js` — 작업공간 `<head>` 에서 앱 스크립트보다 먼저 돈다. `?screen=<id>` 면 지금 화면 상태를 저장하고 그 화면의 상태 묶음으로 전역 키를 바꾼다. `?new=1` 이면 저장 후 비우고 PRD 로(주소에서 지운다).

## 4.4 외부 의존성

| 의존 | 용도 | 방식 |
|---|---|---|
| Pretendard (jsDelivr CDN) | 한글 최적화 폰트 | `<link>` |
| Open-Meteo API | 실시간 날씨(기온·날씨코드) | `fetch()` — 무인증 |
| Browser Geolocation API | 위치 좌표(최초 1회, 서울 폴백) | `getCurrentPosition` |
| html2canvas-pro (jsDelivr CDN) | 화면 PNG 캡처 | 필요 시 동적 로드(`loadScript`) |

> 산출물(사용 매뉴얼)은 Pretendard CDN을 사용한다. 로컬/GitHub Pages에서는 정상 로드되며, 외부 폰트 호스트를 막는 일부 샌드박스 환경에서는 시스템 한글 폰트로 폴백된다.

## 4.5 배포 아키텍처

```
개발(로컬 index.html · studio.html + css/ · js/ · src/ · 문서/)
      │  git push origin main   (origin = hjlee-wemb)
      ▼
┌──────────────────────────┐     ┌──────────────────────────┐
│ origin: hjlee-wemb/       │     │ (미러) localee94/         │
│ WEMB-Studio               │     │ WEMB-studio               │
│  · GitHub Pages 배포       │     │  · 필요 시 별도 동기화      │
└────────────┬─────────────┘     └──────────────────────────┘
             │  GitHub Pages 빌드
             ▼
   공개 정적 사이트 (HTTPS)
   ├─ /index.html                (홈)
   ├─ /studio.html               (작업공간)
   ├─ /css/ · /js/ · /src/       (스타일 · 스크립트 · 템플릿 에셋)
   └─ /문서/사용매뉴얼.html         (요약 안내서)
      /문서/사용매뉴얼_상세.html     (상세 매뉴얼)
      /문서/사용매뉴얼_상세.pdf      (상세 매뉴얼 PDF)
```

- **원격 저장소**: `origin`(hjlee-wemb)에 push하여 배포 — 규칙상 localee94에는 직접 push하지 않음(미러)
- **CI/CD**: 별도 파이프라인 없이 GitHub Pages 정적 배포. 해시 라우팅이라 서버 경로 재작성 설정이 필요 없다
- **캐시 무효화**: 파일마다 `?v=N` — 내용을 바꾼 css/js 는 해당 문서(index.html · studio.html)의 링크 번호를 올린다
- **로컬 실행**: `python -m http.server` 등 http 서버로 연다. `file://` 로 열면 자립형 HTML 내보내기가 분리된 스타일시트를 읽지 못한다(브라우저 CSSOM 보안)
- **롤백**: git 커밋 히스토리 기반

## 4.6 아키텍처 특성 및 트레이드오프

| 장점 | 트레이드오프 |
|---|---|
| 배포·이식 단순(정적 파일 + 문서), 서버 설정 불필요 | 작업공간이 여러 파일(css · js · 템플릿 모듈)을 요청한다 |
| 기능 경계가 폴더 · 파일로 드러나 협업·검토가 쉽다 | 번들러가 없어 `<script>` 순서를 사람이 지켜야 한다(순서 = 의존) |
| 홈이 가볍다 — 스튜디오 DOM · 템플릿 스크립트를 받지 않음 | 홈 → 작업공간 이동은 문서 로드(프로젝트 열기 시 한 번) |
| 주소가 곧 상태 — 새로고침 · 뒤로가기 · 링크 공유 | 화면별 상태는 여전히 전역 키 묶음 교체 방식(브라우저 탭 간 동시 편집 미지원) |
| 인프라 비용/운영 부담 없음 | 서버측 로직·인증·영속 저장 불가 |
| 토큰 기반으로 테마 확장 용이 | 자산 정형화(JSON) 파이프라인 지속 정비 필요 |

## 4.7 향후 확장 방향
- 제작 파이프라인 완성(기능명세서·유저플로우·와이어프레임 자동 생성 고도화)
- 관제 실데이터 연동(WebSocket/REST) — 현재 시뮬레이션 대체
- 시각 자산의 JSON 라이브러리화·Figma 변수 동기화 자동 연계
- 템플릿 화면 스크립트를 열린 템플릿만 지연 로드 — 작업공간 초기 로드 절감
- 규모가 더 커지면 ES 모듈 전환과 번들(빌드) 도입 검토
- 포탈 화면 형식 · 템플릿 갤러리 정식화
