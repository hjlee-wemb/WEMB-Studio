## 1.1 프로젝트 개요

**WEMB Studio**는 관제 대시보드·디지털 트윈 등 **운영 화면을 빠르게 설계·제안**하는 **웹 기반 화면설계 디자인 솔루션**이다. 색 테마 생성·검증·산출 기능을 핵심 수단으로 삼되, 궁극적으로는 **비개발자(디자이너·기획자)도 최신 트렌드로 화면 컨셉을 몇 분 만에 잡고, 레퍼런스·자산을 조합해 고객과 실시간으로 설계·제안**하는 것을 지향한다.

작업은 **프로젝트 런처**에서 시작하며, 새 프로젝트는 **제작 파이프라인**(PRD → 기능명세서 → 유저플로우 → 와이어프레임 → 스튜디오)을 따른다. **PRD**에서 니즈를 질문으로 받으면 뒤 단계가 자동으로 만들어지고, 그 구성이 **스튜디오**에 반영되어 실제 화면 디자인이 완성된다. 포인트 색 하나만 바꿔도 전체 테마가 일관되게 전환되도록 표준화하고, 색 지식이 없는 사용자도 접근성(WCAG) 기준을 충족하는 화면을 만들어 CSS/JSON/Figma/Tailwind 토큰과 개발자 핸드오프 자산으로 산출할 수 있게 하는 것이 목적이다.

## 1.2 추진 배경

- 관제 화면 시안 작업은 손이 많이 가고, 고객 니즈 파악·트렌드 반영에 시간이 걸렸다 → **공수 최소화·트렌드 선제안**이 필요했다.
- 기존 관제 대시보드 디자인(Figma `system` 파일)은 색상이 화면 곳곳에 하드코딩되어, 테마 변경 시 수작업 비용이 컸다 → 색을 **디자인 토큰(변수)** 으로 추상화할 필요가 있었다.
- 대시보드뿐 아니라 **디지털 트윈·포탈 등 화면 유형이 늘어나면서**, 화면 종류·레이아웃별로 일관된 테마를 적용하고 결과를 즉시 확인할 통합 저작 환경이 요구되었다.
- 여러 고객사·시안을 다루기 위한 **프로젝트 단위 관리(생성·검색·즐겨찾기·휴지통)** 의 필요성이 대두되었다.
- 비개발 실무자도 **감각적으로(바이브 디자인) 화면을 설계**하고, **접근성 기준을 자동으로 만족**하는 결과물을 스스로 산출할 수 있는 셀프서비스 도구에 대한 요구가 있었다.
- WEMB의 시각 디자인 자산을 **정형화해 JSON·라이브러리 컴포넌트로 축적**하여 재사용·가속하려는 목표가 있었다.
- 참고 서비스: BairesDev *AI Colors*(색 기반 테마 전환), Pantone *올해의 컬러 2026 (Cloud Dancer)*, Toss(토스) 디자인 언어(요약 안내서 UI).

## 1.3 목표 · 지향점

| 구분 | 목표 |
|---|---|
| 시간 절약 | 손이 많이 가던 시안 작업을 고르고 조합하는 방식으로 단축 (공수 최소화) |
| 트렌드 선제안 | 최신 트렌드 레퍼런스·팔레트를 먼저 제시해 고객이 고르기만 하면 되게 함 |
| 고객과 함께 설계 | 회의 자리에서 즉석에서 바꿔 보여주며 대화로 니즈를 도출 |
| 바이브 디자인 | 코드를 몰라도 디자이너처럼 화면을 만들어 볼 수 있게 함 |
| 접근성 | WCAG AA/AAA 대비비 자동 검증 및 미달 시 자동 보정 |
| 재사용성 | 시각 자산을 JSON·라이브러리 컴포넌트로 축적, 다음 제안에서 재사용 |
| 실증성 | 대시보드·디지털 트윈 등 실제 운영 화면에 실시간 반영하여 결과를 즉시 확인 |
| 확장성 | 화면 종류·레이아웃·Flat/Enterprise 시각 체계, 라이트/다크로 확장 |

## 1.4 주요 기능 요약

1. **프로젝트 런처** — 전체·최근 편집·즐겨찾기·휴지통(복원/영구삭제)·템플릿(준비 중) 뷰, 검색, 새 프로젝트 만들기
2. **제작 파이프라인** — PRD(질문 기반 니즈 정리) → 기능명세서 · 유저플로우 · 와이어프레임(자동 생성, 일부 준비 중) → 스튜디오(핵심 활성 단계)
3. **스튜디오 좌측 레일 5도구** — 화면 정하기 · 색 정하기 · 접근성 검증 · 저장·스냅샷 · 내보내기
4. **화면 정하기** — 화면 형식(대시보드/디지털 트윈/포탈), 버전(Flat/Enterprise), 화면 테마(라이트/다크), 레이아웃(대시보드 2단/3단/모듈 · 디지털 트윈 2·3·4레벨)
5. **색 정하기** — 기준 색(직접색·사진 추출·추천 적용·로고에서 추출·기본값), 배색(Harmony), 현재 팔레트(칩 편집·복사·초기화), 미세조정(H/S/L)
6. **접근성 검증** — WCAG 대비비 자동 계산, AAA 필터, 미달 자동 보정 및 변경 내역
7. **저장·스냅샷** — 스냅샷 명명 저장·불러오기, 되돌리기 기록(타임라인·점프), A/B 비교
8. **내보내기** — CSS 변수 / JSON 토큰 / Figma 변수 / Tailwind / 대시보드 PNG / 팔레트 SVG / 공유 URL / 디자인 사양서(PDF) / 화면 전체 HTML / 컴포넌트별 코드
9. **대시보드 편집 · 에셋 라이브러리** — ＋패널·패널편집, 차트·심볼·아이콘·패널을 검색·드래그로 화면에 삽입(콘텐츠 추가)
10. **시각 체계** — Flat(≤10색) / Enterprise(≤50색) 토글
11. **실시간 요소** — 실시간 시계·날씨, KPI 카운트업, 차트 애니메이션
12. **라이트/다크 모드** — 설정 패널·콘텐츠·팝업 통합 동기화

## 1.5 대상 사용자

| 사용자 | 활용 목적 |
|---|---|
| 디자이너 / 기획자 | 최신 트렌드로 화면 컨셉을 빠르게 잡고, 레퍼런스·자산을 조합해 고객에게 선제안 |
| 고객사 운영자 | 프로젝트별로 관제 대시보드·디지털 트윈 화면을 직접 선택·적용하여 운영 환경에 반영 |
| 내부 PM | PRD로 니즈를 정리하고 설계서 근거(대비비 표·토큰)로 시안·산출물 확보 |
| 개발자 | 산출된 CSS/JSON/Figma/Tailwind 토큰과 핸드오프 자산을 실제 구현에 연계 |

---

## 1.6 기대 효과

- 화면 시안 리드타임 단축(수작업 → 고르기·조합 + 토큰 기반 일괄 전환)
- 고객 니즈 도출을 설계 과정에 내재화(대화가 곧 설계)
- 접근성 기준(WCAG) 위반 리스크 사전 차단
- 디자인–개발 간 토큰 표준화 및 **핸드오프 자산 제공으로 핸드오프 비용 절감**
- 프로젝트·화면 종류·레이아웃 단위 재사용 및 **자산 라이브러리 축적으로 가속**
- 비개발자 셀프서비스로 커스터마이징 대응 부담 완화

## 1.7 현재 상태 (베타)

- 핵심 기능 구현 및 GitHub Pages 공개 배포 운영 중 — **베타 버전으로 계속 개발·업데이트 예정**
- 프로젝트 런처(전체·최근·즐겨찾기·휴지통) 및 새 프로젝트(PRD) 흐름 제공
- 제작 파이프라인 중 **PRD·스튜디오가 실제 동작하는 핵심 단계**이며, 기능명세서·유저플로우·와이어프레임은 자동 생성 기반으로 **일부 준비 중**
- 화면 종류 대시보드·디지털 트윈 지원(포탈·템플릿 갤러리는 준비 중)
- 좌측 레일 5도구(화면 정하기·색 정하기·접근성 검증·저장·스냅샷·내보내기) 및 에셋 라이브러리(드래그 삽입) 제공
- Flat / Enterprise 2개 시각 체계, 라이트/다크 모드, 개발자 핸드오프 내보내기 지원
- (참고) 관제 지표는 현재 **시뮬레이션 데이터** 기반 — 실데이터 연동은 향후 과제
